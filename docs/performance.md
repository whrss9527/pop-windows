# 性能检查

优化覆盖重复图像处理、功能适用性解析、列表重建和剪贴板预览；截图、原文与粘贴内容保持完整。

- 取色、框选与标尺：GDI 位图直接复制为冻结的 BGRA 位图，不再为预览执行整屏 PNG 编码和解码。快照与原位图独立，可在原位图修改或释放后使用；覆盖半透明像素和反向扫描线。
- 取色和标尺在预览建立后立即释放原始 GDI 位图，不再一直持有到操作结束；4K 屏幕的该位图像素区为约 31.6 MiB。标尺确认只返回物理坐标，不裁剪、不编码用不到的 PNG。
- 全部功能搜索：每次打开列表创建适用性缓存，同一功能、同一选区只解析一次；启用状态仍逐次筛选，新选区和重新载入的插件重新判断。边缘「更多」只检查自己的功能。
- 列表方向键：保留未改变的行，仅更新原选中行和新选中行。功能、剪贴板和短语列表共用这条路径，避免反复重建图片及控件。
- 剪贴板长文本预览：只构造所需前缀，保持换行、制表符和空白的原有显示规则，按完整文字元素截断；长尾空白需要扫描，但不再分配整段预览字符串。原文仍完整保留。
- 剪贴板缩略图：在后台解码，同一路径合并请求；最多两张并行，按最近使用保留最多 256 张，最长边 96 像素。256 张 96 × 96 图片按 32 位像素计算为 9 MiB，实际占用还受像素格式、解码器与控件影响。缺失或损坏图片回退图标，同一会话不反复读取；隐藏后取消队列、清空缓存，再次打开重试。
- 隐藏功能、剪贴板和短语浮窗时拆开旧视觉树，释放文本、图片与毛玻璃快照，再次打开重新构建；缩略图任务用会话编号阻止旧结果回填。
- 多文件历史只扫描一次计数，仅分配前三条原始路径；预览截到 120 字符内的完整文字元素，实际粘贴仍使用全部原始文件路径。
- 短语搜索分别检查正文和标题，保留跨标题/换行/正文的匹配规则，不再拼接完整正文；自动标题只读取首行，正文预览限制为 160 字符并保留换行标记，模板展开与粘贴仍使用完整正文。
- 可选行索引只在搜索结果变化时更新；方向键与 Ctrl+数字复用索引，跳过分组和禁用项，不再逐键扫描和分配整组可选项。
- 插件长度条件逐个检查完整文字元素，达到最小长度或超过最大长度时即可判定，不为整段选区创建位置数组；JavaScript 提前完成后撤销兜底计时器，避免长超时任务留下无用等待。
- 插件轻提示只提取第一个非空行的前 60 个完整文字元素，错误摘要只处理前 500 个；`POP_TEXT` 只处理 32,000 个 UTF-16 字符以内的完整文字元素边界，不再为整段输出或选区创建字符位置数组。完整输入仍通过标准输入提供，卡片、复制和替换结果不截断。
- 剪贴板文字与文件去重：短文本在栈上编码，长文本以 4 KiB 缓冲区分块计算 UTF-8 SHA-256，保留代理项及编码回退规则；摘要前缀与现有数据库一致，不需要迁移或重新建立历史。
- 列表按内容调整高度，宽高上限来自所在显示器的工作区，短列表和少量搜索结果不保留大块空白。只在打开时截取一次背景，后续收缩和展开复用快照；键盘仍会将选中行滚动到可见范围。

## 自动验证

核心测试覆盖缓存调用次数、新选区和同 ID 插件重新载入的失效行为，以及查询顺序、功能开关的一致性。

Windows CI 在浅色、深色演示中执行 `PerformanceChecks`：

1. 逐字节核对直接转换与 PNG 路径的像素；验证快照不依赖原位图及反向扫描线方向。
2. 对固定的 1920 × 1080、3840 × 2160 像素输入，预热后各运行三次，记录耗时与托管分配中位数。
3. 创建含分组及禁用项的 100 行列表，验证选择跳过禁用项、反向移动和环绕，三次移动只新增六行控件。
4. 继续执行真实取色、自动/手动标尺、列表键盘选择、选择工具条和剪贴板恢复交互。
5. 对 180 万字符的固定文本记录整段拆分与前缀预览的耗时和托管分配，核心测试验证普通预览一致、emoji 边界和分配不随原文长度增长。
6. 实际解码横向和纵向长图，验证 96 像素上限、冻结、文件句柄释放、会话重开刷新、缺失与损坏文件、缓存淘汰，以及两个后台解码期间清空队列的取消行为。
7. 隐藏并重开真实 WPF 列表，检查旧视觉树和选择已清空，新列表仍可正常使用。
8. 以 10,000 条文件路径和 90,000 字符短语为固定输入，比较文件摘要、短语搜索和预览的托管分配；核心测试对照原搜索规则、路径顺序与数量，验证只改变预览、不改动粘贴内容。
9. 在真实列表中搜索，验证禁用首项、过滤后环绕、Ctrl+数字直选、极大步长和无结果时的选择行为；`list-content=ok` 与 `list-selection=ok` 为必需标记。
10. 在受限的真实 WPF 工作区验证窗口边界、搜索收缩、清除搜索后恢复与末项滚动；检查 `list-sizing=ok`。
11. 通过实际 Shell 通知区域接口注册、修改、撤销图标，投递鼠标/键盘回调和 Explorer 恢复消息，并核对显示器物理坐标与虚拟屏幕范围；检查 `native-tray=ok`，确认没有载入 WinForms。
12. 在真实插件编辑器中控制旧任务迟到、重启、停止和关闭；验证旧结果不回填、不清除新任务进度，8,000 字符结果的界面预览有上限但复制完整；检查 `plugin-editor=ok`。
13. 对 30 万字符选区的插件最大长度条件比较整段计数与边界判定，记录托管分配；核心测试对照复杂 emoji、组合字符与各类长度边界，检查 `plugin-match=ok`。
14. 以 110 万字符的多行输出、200 万字符的选区/错误信息比较插件轻提示、环境变量和错误摘要的托管分配，检查 `plugin-output=ok`；核心测试对照完整文字元素、Unicode 换行和首行空白规则。
15. 对 50 万中文字比较整段编码与分块摘要的耗时和托管分配，检查 `clipboard-hash=ok`；核心测试覆盖块边界处的 emoji、无效代理项与嵌入 NUL，核对既有 UTF-8 摘要格式。
16. 真实插件编辑器检查导入的长度范围、完整 emoji 计数、不匹配原因、未失焦数字输入、反向范围校验、清除条件和修改条件后的任务取消；`plugin-editor=ok` 同时报告 `length=ok pending-numbers=ok`。

## 发布体积

托盘、屏幕枚举、虚拟屏幕和双击设置改用 Windows 原生 API。项目只引用 WPF 与图像处理所需的 System.Drawing.Common；.NET 8 桌面运行时默认仍会复制 WinForms 专属程序集，因此发布目标显式移除 `System.Windows.Forms*`、`Microsoft.VisualBasic.Forms*` 和 `WindowsFormsIntegration*` 的运行时与资源文件。保留 WPF、UI Automation、GDI+、中文字体和自带的 .NET 运行时，不做 WPF 不支持的通用裁剪。

本地候选发布比较：原提交 `fbd3206` 的 Windows CI 程序为 85,981,972 字节，移除 WinForms 并加入本轮界面改进后的候选约 78.2 MB，减少约 9%。最终体积以 Windows CI 的实际文件为准；程序仍为解压即可运行的单个 `Pop.exe`。加入 WinForms 功能时须同步审视发布排除项与原生回归检查。

### 为什么仍有 70 MB 以上

`3fcec3b` 的 Windows CI 实际程序为 78,292,175 字节，ZIP 为 70,613,418 字节。下表按单文件清单中的实际存储字节统计，已经包含包内压缩的效果；MB 使用十进制，不是把原始 DLL 大小直接相加。

| 内容 | 包内占用 |
| --- | ---: |
| .NET 运行时 | 25.38 MB |
| WPF 桌面运行时 | 23.13 MB |
| 单文件宿主、清单与对齐 | 9.72 MB |
| Pop 与中文字体 | 8.25 MB |
| Windows OCR 接口 | 6.32 MB |
| WPF-UI 控件与图标 | 2.73 MB |
| SQLite | 1.31 MB |
| JavaScript 插件解释器 | 1.11 MB |
| 其他依赖与配置 | 0.34 MB |

便携版已经启用单文件压缩；继续整体压缩不会消除运行时。WPF 不支持通用裁剪和 Native AOT，直接删除看似不用的框架 DLL 会影响反射、界面或插件。保留界面程序集的 ReadyToRun，避免为了减包让首次弹出重新承担编译成本。

### 可选轻量版

从 0.10.0 起同时生成 `Pop-<版本>-win-x64-lightweight.zip`：以 `--self-contained false` 发布，复用电脑上已安装的 **.NET 8 桌面运行时 x64**。保留同样的字体、OCR、截图、SQLite、JavaScript 插件和界面预编译。本地候选 EXE 约 48.0 MB，ZIP 约 18.2 MB，相比上面的 ZIP 减少约 74%；SDK 不支持给依赖框架的单文件启用包内压缩，因此应分别比较 EXE 和 ZIP。

没有运行时的电脑必须先安装；普通 .NET Runtime、x86 或其他主版本不能替代。第一次安装运行时有额外下载与磁盘占用，轻量版主要节省重复携带和后续更新流量，不代表运行时、总安装空间或进程内存消失。无需另装依赖时继续使用便携版。

更新根据编译时包型选择资产，两种 ZIP 共用包含各自条目的 SHA-256 清单；缺少同包型资产时跳过该发布，不自动切换包型。CI 对两种包分别执行 Windows 2022/2025 的启动、手势、交互与浅深色截图；更新端到端测试提供一个故意不可用的另一包型资产，检查正确下载、拒绝错误校验和，以及更新重启后包型不变。

可独立复核任何 .NET 8 发布文件，无需运行 Windows 程序或安装第三方 Python 包：

```bash
python scripts/measure-package.py out/new/Pop.exe out/lightweight/Pop.exe --json out/package-sizes.json
```

脚本只读单文件清单与依赖清单，区分实际存储字节和解压字节，不改写程序；CI 的 `pop-exe` 工件也保存这份统计。

结果在截图分支 `ci-screenshots/windows-2022`、`ci-screenshots/windows-2025` 的 `ui/light-demo.txt` 和 `ui/dark-demo.txt` 中。先核对分支 README 中的提交号，再查看 `screen-snapshot=ok`、`list-navigation=ok`、`text-preview=ok`、`clipboard-thumbnails=ok`、`overlay-release=ok` 和 `performance:` 行。

`png-ms`、`direct-ms` 仅比较相同输入的图像转换，不代表完整工具启动时间；`managed-bytes` 不含 WPF/WIC 的原生内存，不能作为进程总内存。CI 不对耗时设置硬阈值，以免共享运行器负载波动产生误报。

## 在 Windows 单独运行

```powershell
$env:POP_SMOKE_MARKER = Join-Path $PWD 'performance.txt'
Start-Process .\Pop.exe -ArgumentList '--demo-shots', 'performance-shots', '--demo-scenes', 'performance' -Wait
Get-Content $env:POP_SMOKE_MARKER
Remove-Item Env:POP_SMOKE_MARKER
```
